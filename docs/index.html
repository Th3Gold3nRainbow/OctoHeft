The 99% freeze, explained

A classic download manager fetches a file in several parts, stores them in temporary files, then copies them one by one into the final file. OctoHeft removes that step.

IDM pipeline

Temporary files, then concatenation
Each connection writes its own temporary file
99% barrier: every part is read and copied again
Final file only created at the very end
  • 30 seconds to 5+ minutes of waiting on large files
  • Data written twice to the SSD
  • Free space needed: 2 × the file size

OctoHeft pipeline

Direct writes, zero assembly
Final file created as soon as the HTTP headers arrive (NTFS sparse allocation)
Each connection writes at its exact offset
Done the instant the last packet arrives
  • 0 ms of assembly
  • A single write pass on disk
  • Free space needed: 1 × the file size

Plugs into your browser

Manifest V3 extension for Chrome, Edge, Brave and Firefox. Downloads are intercepted and handed to OctoHeft along with your cookies, User-Agent and Referer, so protected sites keep working.

The browser detects

Archives, executables, documents and media are intercepted. Video streams are spotted automatically.

Native message

The extension sends a JSON frame to OctoHeft.exe through Native Messaging.

OctoHeft downloads

If the app is running, the job arrives over a named pipe. Otherwise it is queued and resumed at launch.
